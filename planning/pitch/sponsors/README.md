# Sponsor challenge briefs

One brief a challenge, so that the team can say in thirty seconds how this project meets that sponsor's ask, with the evidence behind every claim.
Written 2026-09-20, from `../../plans/deploy-and-sponsor-briefs-2026-09-20.md`, through the `hackathon-pitch` skill.

## The open item on both

Neither brief quotes the sponsor's actual challenge text, because the day-of prizes page needs a login and the planner would not write a judging criterion from memory or from a search snippet.
Section 1 of each brief is a marked gap.
abba pastes the real text in, and then each brief is checked against it rather than assumed to fit.

Everything in sections 2 onward is an account of what the repository actually contains, so it does not depend on the wording of the challenge.

## Which challenges are not entered, and why

- A hardware challenge is out, because nothing physical was built.
- Long Lakes wants an AI explainer, which this project does not have, and adding one would contradict the project's own claim that no learned model is in the loop.
- Any other challenge on the official list is abba's call, and a brief is written only after abba says yes.

## The rule both briefs follow

Every sentence about Devin, a dataset or a figure names the file, the pull request or the command it came from, and says whether checked-in code reproduces it.
Where the repository does not hold a fact, the brief says so instead of filling the space.
