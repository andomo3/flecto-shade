# Meeting 2026-09-04

Ingested from the team's planning doc, see Sources.
The doc records plans and role splits rather than explicit votes, so the decisions below are read from what the team chose to plan in detail.

## Decisions

- The field has narrowed to three build plans: the morphing tensegrity structure, the impact helmet, and the AI that evolves biomimetic structures, because these are the ideas the doc plans step by step with owners.
- The gecko foot stays on the table with its notes unchanged from 2026-09-02, because the doc carries them over without a build plan.
- Bee-hive modular architecture, ChatGPT idea 14, is folded into the AI that evolves biomimetic structures, idea 25, because the doc heads that section "25 and 14 combined".
- The tensegrity plan is the morphing module with pulley and string per module, not the catalog's impact cage, because the doc plans the module and never mentions the cage.
- Tensegrity control goes through simulation: build an MJCF model in MuJoCo, write a fitness function per target pose, and run CMA-ES to tune string lengths for two to four poses before touching hardware.
- The impact idea is framed as a full helmet printed in small chunks, with a drop test rig, a data pipeline, and a language model safety report and dashboard, because the doc's five steps say so.
- Work is split by role for each plan: CAD, embedded systems, an RL teammate, an ISE teammate, ops and backend, and ML.
  The doc names roles, not people, so the idea files carry the role splits until the team maps names to roles.

## Status changes

- evolved-biomimetic-structures: proposed -> researching, now has a concept, a research question, and a software framing
- beehive-modular-architecture: proposed -> rejected as a standalone idea, folded into evolved-biomimetic-structures

## Who researches what next

- CAD person: sketch the tensegrity base structure and two to four target poses, and check each is buildable, due next meeting.
- RL teammate with ISE teammate: stand up an MJCF model of one tensegrity module in MuJoCo and confirm CMA-ES converges on one pose in under a few hours.
- CAD person: pick an open source lattice generator for the helmet and test print one small chunk in TPU.
- Embedded systems person: design the drop test mechanism and sensor rig shared by the helmet and any coupon test.
- ML teammate: define what the evolved structures optimiser scores, simulation or a physical rig, and how the language model fits the loop.
- Team: map names to the roles in the two owner tables.
- abba: 3D printing access, still open, and now load bearing for all three plans.
